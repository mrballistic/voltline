# Voltline 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Voltline 1.1.0: rocks from level 5, harder refills and more rocks past level 8, tray counting that pauses while the tray is full, a reliable tray drag with visible refusals, and a Claude Design UI brief.

**Architecture:** Difficulty and tray rules change only in the pure engine (`src/engine/rules.ts`, `gravity.ts`, `tray.ts`); the AI picks them up automatically because it simulates through the same engine. Removing the `tray-lost` step ripples through types, planner, player and the cue manifest. The tray drag fix lives in `src/render/input.ts` after a Playwright repro. The brief is a new doc.

**Tech Stack:** unchanged from 1.0 (Node 26, React 19.3, TypeScript 6.0, Vite 8, Vitest 5, PixiJS 8, GSAP 3, MUI 9, Playwright).

**Spec:** `docs/superpowers/specs/2026-11-13-voltline-1-1-design.md` (and the 1.0 spec it builds on). Read `CLAUDE.md` and `ARCHITECTURE.md` first.

## Global Constraints

- Every invariant in `CLAUDE.md` holds (engine/ai pure and seeded, tunables only in their homes, strict CSP, no network calls, no `console.log`, curly punctuation in user-facing copy).
- Work on branch `voltline-1.1` (or a worktree branch made from it). Commit email `mrballistic@gmail.com`; commit messages end with a `Co-Authored-By:` line naming the model that wrote the commit.
- Rule numbers live only in `src/engine/rules.ts`; animation timings only in `src/render/constants.ts`.
- Parallel tasks do not edit `README.md` or `CHANGELOG.md`; they put the copy they want in their report and the controller folds it in.
- Full gate before reporting: `npm run type-check && npm run lint && npm run test:run && npm run build`; tasks that touch input or audio also run `npm run smoke`.

## Review Focus

1. **Determinism after the refill change:** a seed + move list still replays to the same script and state (pinned in Task 1).
2. **AI honesty:** stinginess must come from the game RNG inside the engine; the AI's own RNG drives it in simulation, so `rankMoves` still ignores the hidden `rngState` (pinned in Task 1).
3. **Fresh boards stay playable at high levels:** at level 16 with 18% rocks, `createBoard` still returns no ready matches and at least one productive move, quickly (pinned in Task 1).
4. **Tray rule edge:** a clear that fills the tray mid-round must not count the rest of that round's clears (pinned in Task 2).
5. **Drag refusals are visible and never wedge input:** a refused drop shakes and flies home, and the next drag works (pinned in Task 3).

### Task 1: Difficulty: rocks from level 5, stingy refills and more rocks past level 8

**Files:** Modify `src/engine/rules.ts`, `src/engine/gravity.ts`, `src/engine/rules.test.ts`, `src/engine/gravity.test.ts`, `src/engine/board.test.ts` (if a pinned rate moves), `src/ai/weights.ts` (only if the bench says so), `ARCHITECTURE.md` (engine section).

**Interfaces:**
- `ROCK_START_LEVEL = 5`.
- `rockChance(level)`: `0` below 5; `0.03 + 0.01 × (level − 5)` for 5–8; past 8 `0.06 + 0.015 × (level − 8)`, capped at `0.18`.
- New `STINGY_START_LEVEL = 9` and `stinginess(level): number` = `0` below 9, else `min(0.1 × (level − 8), 0.6)`.
- `applyGravity(board, rng, level, nextId)` signature unchanged. Spawns are placed column by column left to right, top row first (unchanged). For each spawned gem, if it would complete a 3-in-a-row of its color with the pieces already settled around its final cell (in that column below it, and in its row to the left and right, counting earlier spawns of this pass), then with probability `stinginess(level)` re-roll it once to a color that would not complete a run (uniform among those colors; keep the original if none exist). Rocks are never re-rolled. All draws from `rng`.

- [ ] **Step 1: Failing tests.** `rules.test.ts`: rockChance at 4 → 0, 5 → 0.03, 8 → 0.06, 9 → 0.075, 16 → 0.18, 30 → 0.18; stinginess at 8 → 0, 9 → 0.1, 14 → 0.6, 20 → 0.6. `gravity.test.ts`: `stingy refills avoid ready matches at high levels` (over 500 seeded gravity passes on a fixture where a refill in column 0 sits above two reds, the share of red refills completing the run is measurably lower at level 14 than at level 1); `no stinginess below level 9` (identical output for levels 1 and 8 given the same rng state, rocks aside); `replay stays deterministic` (same seed and board → identical spawns). `board.test.ts`: `level 16 boards stay playable` (200 seeds: no matches, a productive swap).
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement. **Step 4:** Run engine and AI tests → PASS (`ignores the hidden rng` must still pass).
- [ ] **Step 5: Bench.** Dry run `npm run bench -- --games 1 --max-moves 50`, then `npm run bench -- --games 20 --max-moves 400`. Report before/after (mean level, score, AI/baseline ratio, game-overs, decision p95). The bar: ratio ≥ 1.5×, mean AI level noticeably below 1.0.1's ~14, games still reach level 10+. Adjust only `src/ai/weights.ts` if the ratio fails; report any change.
- [ ] **Step 6:** Commit `make rocks start at level 5 and refills stingier past level 8`. Report README copy for the Rocks paragraph and a CHANGELOG bullet.

**Interfaces:**

When an earn fills the tray, every counter resets to 0 immediately, so later clears in the same `cleared` list are not counted. Emits `tray-earn` and `tray-full` as today; never `tray-lost`.
